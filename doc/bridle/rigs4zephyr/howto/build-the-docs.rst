Building the documentation
============================

The documentation is built with the **workspace Python environment** — the
same ``.venv`` at the west workspace root that ``mypy`` and ``pytest`` run
from. There is no separate documentation environment: ``btr-shields`` is a
Zephyr module, not a Python distribution, so there is nothing to
``pip install -e`` and nothing that a second environment would isolate.

Install the tooling
---------------------

Once, into the workspace environment:

.. code-block:: console

   $ pip install sphinx sphinx-rtd-theme sphinx-rtd-dark-mode

Build once
------------

From the ``btr-shields`` checkout, with the workspace environment active,
build the HTML docs with warnings treated as errors — the same command
that gates a documentation change:

.. code-block:: console

   $ sphinx-build -W --keep-going -b html doc doc/_build/html

``-W`` is not optional. A broken ``:doc:`` link, an unresolved ``:term:``,
or a page missing from a toctree is a build failure, which is what keeps
:doc:`../explanation/documentation-guidelines`'s "no orphan pages, no
dangling references" rule true rather than aspirational.

Then open ``doc/_build/html/index.html``.

The :doc:`../reference/api/index` pages are generated by ``autodoc``,
which **imports** every ``rigc`` module to read its docstrings. That works
with no Zephyr tree present and no ``ZEPHYR_BASE`` set — the expander's
``devicetree`` imports are all deferred into function bodies — so a
documentation build needs nothing beyond the packages above.

Live preview while editing
----------------------------

.. code-block:: console

   $ pip install sphinx-autobuild
   $ sphinx-autobuild doc doc/_build/html

Then open the URL it prints (typically ``http://127.0.0.1:8000``).

Checking cross-project links
------------------------------

References into the Zephyr documentation resolve through intersphinx
against a live ``docs.zephyrproject.org``. Those are deliberately not
fatal, so the build still works offline; references *within* this tree
always are.
